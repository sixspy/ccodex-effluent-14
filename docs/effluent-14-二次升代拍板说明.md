## 一、为什么是甲，不是乙

独验收段硬性要求：**"采样页同口再采时旧批必须作废标记"**、**"废旧与升新须同事务跨表"**。
这正是甲路径的定义。乙路径"再采只落影子、旧批正式零改"与该验收项直接冲突，故不采用。

## 二、甲路径唯一正确性口径（封死）

> 同一排放口二次采样（升代）时，**作废旧代与升新代正式必须是同一事务内的跨表双写**：
> 旧代 `sample_batches.status` 置 `作废`（写 `voided_at / void_reason / superseded_by`），
> 新代以 `generation = 旧代最大代 + 1`、`gen_state='正式'` 直接正式入库，
> 并在同一事务写 `metric_lineage` 的"二次升代"父子边与 `regen_runs` 拍板留痕。
> 任一步失败，**整笔回退**——旧代不得被废，新代不得残留。

互斥不变量：

1. 一个排放口同一时刻至多一个具正式效力的世代（`已裁定 / 已准排 / 已封批` 且非 `作废 / 影子`）。
2. 同口二次采样必须抢 `outfall:{outfall_id}` 口锁；两路会话同抢，胜方写入，败方 HTTP 409 且**只留争用痕**（`contention_log`），不得写批次/血缘。
3. 对账只计一个正式世代；`影子` 新代未升正一律 `counted=false`，双计灯必须灭；若库里仍存在同口双正式，双计灯亮报警。
4. 封批服务对 `作废` 旧代 / `影子` 代一律拒绝升代封批（409）。
5. 血缘页默认只看 `is_current=1` 的新代父子边；旧边置 `is_current=0` 留档但不上页。
6. 排放口页同口默认只展示新代（当世代）。

## 三、乙路径与"折中"的处置

- **不提供乙路径写入面**：不存在"先落影子新代、日后原子升正"的二次采样入口。
- 但对账服务保留乙口径的**反向哨**：任何来源（含事故夹具、直插库）的 `影子/未升正` 行都必须识别并剔除，不得双计。这是防双计读模型，不是第二写入路径。
- 任何请求或说明试图在甲之外混入乙/影子/稍后升正/双口径/折中（请求字段 `strategy=乙|B|shadow`、`shadow=true`、`promote_later=true`、文案含"折中/hybrid"等），一律：
  1. 独立连接持久化审计动作 **`二次升代偏航`** 与 `regen_deviation_log`；
  2. **拒写**（HTTP 422），业务数据零落地。
- 本说明当日封死后不得追加"折中/双口径"条款；任何对封死结论的改写请求同样按"二次升代偏航"留痕并拒写。
